# 🏛️ NNL (Neural Network Lego) — Архитектурная система

**NNL** — это модульный архитектурный стандарт для композиции специализированных нейросетевых блоков через общую шину данных и двухтактовую диспетчеризацию.

Система решает фундаментальную проблему композиции моделей: **изоляция на входе (Lego-индекс = 0.0000) и согласованность на выводе (причинное уточнение).**

---

## 5 Уровней архитектуры

```
[Пользовательский запрос]
         │
         ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. МАТПЛАТА (матплата.py)                                   │
│    Физические слоты, sha256 весов, общая шина данных        │
└──────────────┬───────────────────────────────┬──────────────┘
               │                               │
               ▼                               ▼
┌───────────────────────────────┐ ┌───────────────────────────┐
│ 2. БЛОКИ (Слоты 1..N)         │ │ Срез шины:                │
│    Паспорта, независимые веса │ │ Такт 1: {} (Lego = 0)     │
│    Собственные архитектуры    │ │ Такт 2: подтвержд. факты  │
└──────────────┬────────────────┘ └────────────┬──────────────┘
               │                               │
               ▼                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. ПРОЦЕССОР ТАКТОВ (процессор.py)                          │
│    Диспетчер тактов 1 и 2, обратная запись уверенных фактов │
└──────────────┬──────────────────────────────────────────────┘
               │
      ┌────────┴────────┐
      ▼                 ▼
┌────────────────┐ ┌──────────────────────────────────────────┐
│ 4. ЯДРО (ядро) │ │ 5. РЕШАТЕЛЬ (решатель.py)                │
│ Причинный граф │ │ Селективный классификатор:               │
│ понятий шины   │ │ ответ (точность 80–94%) vs «не знаю»     │
└────────────────┘ └──────────────────────────────────────────┘
```

1. **Слой 1. Матплата (`матплата.py`)** — физические слоты, хот-плаг, проверка контрольных сумм sha256, изолированный срез шины.
2. **Слой 2. Блоки** — независимые модели, соответствующие [Стандарту блока](СТАНДАРТ_БЛОКА.md).
3. **Слой 3. Процессор тактов (`процессор.py`)** — двухтактовый диспетчер. Не знает имена блоков (работает с любым $N$).
4. **Слой 4. Ядро причинности (`ядро.py`)** — валидация графа понятий на шине, независимая от имен блоков.
5. **Слой 5. Селективный решатель (`решатель.py`)** — отсекает шумные гипотезы по маржину $\Delta = s_{(1)} - s_{(2)} \ge \tau$, ликвидируя 41 слепую ошибку argmax.

## Быстрый запуск

### 1. Запуск комплексного теста архитектуры:
```bash
python NNL/тест_системы.py
```

### 2. Проверка соответствия блока стандарту NNL:
```bash
python NNL/линтер.py <путь_к_папке_блока>
```

## Сквозной сценарий

Человек пишет словами жалобу или результат обследования; система находит статью Расписания болезней и называет категорию годности
(А, Б, Б-3, В, Г, Д) **только если есть подтверждение врача**. Решает код (блоки, ядро, решатель); модель только слушает и пересказывает готовое решение.
Два входа, по которым проверяется первая готовая версия:

1. «Мне 19. Окулист в поликлинике после капель написал: близорукость −7 дптр на оба глаза. Что в итоге?»
   Ожидание: ст. 34, пункт «в» (более 6,0 и до 8,0), категория В — ограниченно годен.
2. «Сам решил, что у меня минус семь, к окулисту не ходил. Что в итоге?»
   Ожидание: без подтверждения врача категорию годности не называет.

```bash
python -X utf8 NNL/диалог/диалог.py "текст реплики" ...   # живой диалог в терминале, каждая реплика — аргумент
python -X utf8 NNL/диалог/сервер.py 8091                  # стенд (свой порт — 8090 занят), вкладка «Диалог»
```

## Подключение новых блоков

Чтобы подключить в систему Блок 4, Блок 5 или Блок 100:
1. Создайте папку блока с файлом весов `веса.npz` и манифестом `паспорт.json`.
2. Проверьте блок через линтер: `python NNL/линтер.py <папка_блока>`.
3. Подключите к матплате одной строкой: `матплата.подключить(папка_блока)`.
Ни единой строчки кода в Процессоре или Ядре менять **не требуется**.

Перед подключением нового блока к работающей системе проверьте, что он не меняет ответы соседей (допуск ε по умолчанию 1 %):
```bash
python NNL/линтер.py <папка_нового_блока> --вставка <папка_соседа_1> <папка_соседа_2> [--эпсилон 0.01]
```

## Защита от каскадных ошибок

Ошибка на раннем шаге не должна расти по цепочке «разбор → оценка блоком → учёт → вопрос → итог» и «блок → шина → соседи». Что сделано и с какими числами —
в [`каскады/ОТЧЁТ.md`](каскады/ОТЧЁТ.md). Коротко:

* **шина** (`матплата.py`): значения хранятся по источникам; «да» одного блока против «нет» другого — конфликт, понятие не пишется ни в один срез,
  результат не зависит от порядка блоков; согласные блоки не складываются;
* **процессор** (`процессор.py`): передаёт источник записи, возвращает `конфликты`; необязательный `предел_влияния` (по умолчанию выключен: замер показал компромисс);
* **линтер** (`линтер.py`): проверка вставки блока — ответы соседей меняются не более чем на ε, такт 1 соседей не меняется, после снятия всё как было;
* **ядро диалога** (`диалог/расследование.py`, приложение, не архитектура): журнал улик с пересчётом с нуля, снятие улик при поправке человека, потолок на
  зависимые упоминания одной реплики, сверка разбора модели со словами самого человека.

Проверка (сети не нужно):
```bash
python NNL/тест_защиты.py                      # шина, процессор, линтер: 23 проверки
python NNL/диалог/тест_защиты_диалога.py       # журнал улик и сверка: 28 проверок
python NNL/диалог/тест_следа.py                # прежний автотест, 40 из 40
python NNL/каскады/стенд_диалога.py --профиль до     # стенд: усиление ошибки по стадиям диалога («до» — замороженное ядро)
python NNL/каскады/стенд_диалога.py --профиль после
python NNL/каскады/стенд_шины.py --профиль до        # стенд: каскад через шину, рост числа блоков, согласованный сбой, конфликт
python NNL/каскады/стенд_шины.py --профиль после
```

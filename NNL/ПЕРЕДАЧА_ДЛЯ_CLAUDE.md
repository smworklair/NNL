# 🤝 Передача проекта для Claude: Архитектура NNL (Neural Network Lego)

Этот документ подготовлен для быстрой передачи контекста Claude. Здесь зафиксированы решённая проблема, доказанные метрики, структура папки `NNL/` и техническое задание (ТЗ) на следующие этапы.

---

## 1. Контекст: с чего всё началось и что было исправлено

### В чём была проблема (застревание в v8):
1. **Антикоррелированные ошибки (24 / 20 / 17 / 0):** на стыковых вопросах один блок отвечал верно, а второй угадывал не по теме.
2. **Слепой argmax:** система форсировала выбор гипотезы даже при нулевой уверенности, генерируя 41 уверенную ошибку.
3. **Зашумление шины на Проходе 1:** шина наполнялась из сырых токенов вопроса до формирования вывода, что разрушало изоляцию ($Lego = 0.1822$).
4. **Хардкод в ядре:** код ядра содержал `if имя_блока == "здоровье"`, что блокировало масштабирование на $N \to 100$ блоков.

### Что сделано и верифицировано:
* Разделена система на 5 уровней: **Матплата &rarr; Блоки &rarr; Процессор &rarr; Ядро &rarr; Решатель**.
* Реализован **Контракт изоляции на Такте 1**: $Lego = 0.0000$ (строго 0/461 искажений на `bench.jsonl`).
* Реализована **Двухтактовая диспетчеризация**: подтверждённые выводы Такта 1 пишутся на шину, зависимые блоки уточняются на Такте 2.
* Добавлен **Селективный решатель**: калибровка по маржину $\Delta = s_{(1)} - s_{(2)} \ge \tau$ дала точность $80.4\% \dots 94.3\%$ на отвеченных при контролируемом воздержании («не знаю»).
* Все веса блоков v8 сохранены без переобучения; Блок 3 (`ответы_мейлру`) подключён и генерирует живой совет.
* Создана чистая папка `NNL/` без предметного хардкода.

## 2. Ключевые файлы в `NNL/`

| Файл | Назначение |
|---|---|
| `NNL/матплата.py` | Физические слоты, хот-плаг, sha256 весов, изоляция шины на Такте 1. |
| `NNL/процессор.py` | Двухтактовый диспетчер для любого $N$ блоков (без `if имя == ...`). |
| `NNL/ядро.py` | Причинный валидатор графа понятий шины. |
| `NNL/решатель.py` | Селективный классификатор (порог $\tau$, кривая воздержаний). |
| `NNL/линтер.py` | Валидатор соответствия папки блока стандарту (`python NNL/линтер.py <папка>`). |
| `NNL/тест_системы.py` | Эталонный прогон архитектуры (`python NNL/тест_системы.py`, время 1.6 с). |
| `NNL/СТАНДАРТ_БЛОКА.md` | Спецификация манифеста `паспорт.json` и интерфейса методов. |
| `NNL/README.md` | Архитектурная документация 5-уровневой системы. |

## 3. Архитектурные инварианты (НЕЛЬЗЯ нарушать)

1. **Lego-индекс = 0.0000:** На Такте 1 срез шины для любого блока **всегда строго пуст `{}`**. Вынимание любого блока из матплаты не должно менять соло-отклик остальных.
2. **Никакого хардкода имен блоков в ядре и процессоре:** Никаких `if block == '...'`. Блоки оперируют через манифесты (`паспорт["проекции"]`) и шину.
3. **Запрет слепого argmax:** Все решения принимаются через селективный Решатель по маржину уверенности $\tau$.

## 4. Техническое задание (ТЗ) для Claude

### Задача 1. Разработка формального DSL языка NNL (NNL Concept Syntax)
* Сейчас понятия на шине — это плоские строки (`глава:11`, `акт:53фз`).
* **Требуется:** Разработать формальную спецификацию синтаксиса понятий (DSL) с поддержкой:
  - Пространств имён (`domain:category:entity:attribute`).
  - Логических предикатов для шины (`AND`, `OR`, `NOT`, `REQUIRES`, `EXCLUDES`).
  - Вероятностных шкал и доверительных интервалов.

### Задача 2. Обучение и добавление новых блоков (Блок 4, 5, ... N)
* Обучение новых специализированных моделей под стандарт `NNL/СТАНДАРТ_БЛОКА.md`:
  - Блок отсрочек (IT, образование, семейные обстоятельства).
  - Блок судебных процедур (КАС РФ, административные иски).
  - Блок военно-врачебных комиссий (КМО).
* Прогон каждого нового блока через `python NNL/линтер.py <папка>`.

### Задача 3. Развитие Причинного Ядра (Causal Inference Engine)
* Перевод `NNL/ядро.py` с табличных правил на ориентированный ациклический граф (Causal DAG).
* Механизм проверки причинной непротиворечивости между выводами произвольного числа $N$ блоков.

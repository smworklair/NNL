# Наблюдение за системой и рассуждение в стенде

## Идея: API — следователь, а не детектив

**NNL + API (следователь).** Факты собирают и фильтруют блоки и ядро. API получает уже готовое досье и только слушает человека и пересказывает. Выдумать факт ему не из чего: его вход ограничен. Решения (что спросить, когда закончить, можно ли называть категорию) принимает ядро, не API.

**API (детектив).** Модель ведёт дело сама: берёт факты из собственной памяти и строит выводы. Сильная модель (например, Qwen 3.8 Max) справится и так, но потратит в разы больше токенов. Вопрос в цене решения.

Из этого следует, что наблюдать нужно за всей системой, а не за знанием одной статьи: что сделали блоки, что решило ядро, что именно получил API и что он ответил, что отсекла охрана.

## Что видно на странице

Запрос → шаги работы вживую → шаги сворачиваются в «Работало N с ›» (раскрыть можно) → ответ.

Шаги пишет код системы в момент работы, ничего не досочиняется задним числом:

| Участник | Что делает |
|---|---|
| Блоки | Оценивают область вопроса и фразы. Ничего не решают |
| Ядро | Считает вероятности по статьям, проверяет вопросы API, решает: спросить / итог / вне темы, допускает вердикт по категории |
| API | Слушает, предлагает вопросы, пишет текст. У каждого вызова видно: что передала система, что он ответил, его рассуждение |
| Охрана | Сверяет числа и ссылки с документом, не пускает категорию без врача |

Кнопка **Думать глубже** просит у API подробное рассуждение для ролей «вопросы», «итог», «речь» и режима «API». Разбор реплики остаётся быстрым: проба показала 69 с и 3,5 тыс. токенов рассуждения вместо 2 с на ту же запись со слов.

## Рассуждение API по провайдерам

Проверено живыми вызовами 12.10.2026, простой вопрос «17+25».

| Модель | Без «глубже» | С «глубже» |
|---|---|---|
| Groq `openai/gpt-oss-120b` | есть, короткое | подробнее |
| Alibaba `qwen3.8-flash` | нет (`enable_thinking=false`) | есть, `reasoning_content` |
| Gemini `gemini-3.8-flash` | нет | есть, в тегах `<thought>` |
| Groq `qwen/qwen3.8-27b` | нет | нет (`reasoning_format=parsed` не помог) |

Если провайдер рассуждения не отдал, страница так и пишет, ничего не подставляя.

Настройка лежит в `провайдеры.json` (`extra_body_размышление`). Если провайдер не принял такое поле (HTTP 400), клиент один раз повторяет запрос без него.

## Журнал и аудит

* Страница отправляет на сервер нажатия, выбор в списках и Escape (`POST /api/событие`). Текст, который человек печатает, туда не попадает: он приходит ходом диалога.
* Ход со следом сохраняется в `журнал_работы/<сессия>.jsonl`. **В журнале слова человека**, папка в `.gitignore`.
* Бенчмарки → «Журнал сессий» → «открыть»: хронология нажатий и шагов системы, метрики хода и проверки.

Проверки считаются кодом по следу, без модели-судьи (`наблюдение.py`):

| Проверка | Смысл |
|---|---|
| `след_полон` | Нет «повисших» вызовов, у каждого вызова записаны вход и выход, время не идёт назад, последний шаг «Ответ готов» |
| `решение_до_слова_API` | Ядро решило раньше, чем заговорил API (где ядро есть) |
| `ссылки_в_границах_досье` | Статьи в ответе только из того, что API видел во входе (где API участвовал) |
| `числа_в_границах_входа` | Числа с единицами в ответе только из входа API или слов человека |
| `категория_только_с_врачом` | Категория годности звучит только если врач подтвердил что-то |
| `нет_слов_про_систему` | API не говорит человеку про «систему», «алгоритм», «вероятность» |

## Бенчмарк «Наблюдение за системой»

Те же сценарии идут в двух режимах: «NNL + API» и «API». Для каждого считаются проверки, токены, вызовы, время, сколько утверждений вышло за границы входа и отдал ли API рассуждение. Результат: сводка, сравнение режимов и следы сценариев (кнопки «NNL + API» / «API» раскрывают шаги). Кэш ответов в этом тесте отключён: иначе повторный вызов выглядит бесплатным и сравнение цены нечестное.

### Пара «следователь=>детектив»

Кандидат вида `alibaba:qwen3.8-flash=>alibaba:qwen3.8-max` (можно ввести в поле «провайдер:модель») запускает «NNL + API» на первой модели, а «API» сам на второй. Так проверяется вопрос цены решения: дешёвый следователь при блоках и ядре против сильной модели, которая ведёт дело сама.

Первый замер (12.10.2026, 4 сценария, без кэша):

| | Токены | Вызовов | Вне границ входа |
|---|---|---|---|
| NNL + API, Qwen 3.8 Flash | 21 506 | 15 | 0 |
| API сам, Qwen 3.8 Max | 4 847 | 7 | 6 |

**Оговорка.** Режим «API» здесь — обычный чат: один вызов на реплику, без инструментов и без доступа к блокам и документу. Он дёшев и ничем не подкреплён (6 утверждений вне границ). Гипотезу «детектив тратит в разы больше токенов» этот замер не проверяет: для неё нужен режим, где модель сама проходит весь процесс (ходит к блокам и документу в несколько шагов). Такого режима пока нет.

Лимит Groq (8000 токенов в минуту на модель) делает прогон на одной модели Groq очень медленным: в пробе первый сценарий не завершился за 4 минуты. Для прогонов лучше брать Alibaba или пул моделей.

«Пороги статьи 34» и «Дисциплина отказа» остались, но помечены как предметные (про одну статью) и по умолчанию не выбираются.

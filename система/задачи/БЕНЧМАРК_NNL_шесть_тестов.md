# NNL против чатов: шесть тестов, 14 октября 2026

Полный отчёт по бенчмарку. Каждая цифра либо посчитана скриптом по ключу (`NNL/диалог/бенч_шесть/счёт.py`, `перебор_тест6.py`), либо взята из ответа модели, который вставил автор. Всё, что не измерено, помечено. Рабочие заметки лежат в [шпаргалке](шпаргалка_доклад.md).

## 1. Коротко

- **NNL без API в решении** (ядро, блоки и решатель, а модель только слушает) на тестах 1–4 даёт: **67–71 верная статья из 88** (тест 1), **24/24 пункта и категорий на порогах** (тест 2), **0 ложных «да»** (тест 3), **0 категорий без врача и 6/6 статей с врачом** (тест 4). Токенов на тестах 1–3 — ноль.
- Лучший из чатов на тесте 1 называет **32 верные статьи** (Grok), остальные — 1–31. На тесте 2 пороги верно применили NNL, Gemini Argon 4 и Grok (по пунктам), у остальных 6–18 из 24, с ошибками на границах «более/до».
- На тесте 4 без врача **ни одна модель не назвала категорию** (0 из 8 у всех). Но с врачом чаты выдумывают номера статей (Opus: астма — ст. 48 вместо 52), а модель без блоков на той же Groq-модели вообще не угадала ни одной статьи (0/6, номера 33, 44, 45).
- Тест 6 (исследовательская задача без предметной области) выиграли Sonnet 5.5 (19/24) и Haiku 5.5 (15/24). **Для NNL этот тест неприменим**: блоков под него нет.
- Тест 5 (диалог с поправками): NNL по замыслу задаёт вопросы, а в режиме ответа решает 6 диалогов из 8 по делу. Два не решены (разбор ниже). Ключа нет, оценка качественная.
- **Главная честная оговорка**: фразы теста 1 — из отложенной части того же набора, на котором учились блоки, и у NNL есть документ, а у чатов его нет. Это сравнение «система с документом и обученными блоками против модели из памяти», а не «модель против модели».

## 2. Что мерили и зачем

Три обещания NNL 0.1, на которые смотрят тесты:
1. **Следователь, а не детектив**: факты собирают блоки и ядро, модель только пересказывает. Проверка: тесты 2, 3 (не выдумывает ли системa числа, статьи и пункты).
2. **Честное «не знаю»**: воздержание вместо слепого выбора. Проверка: тесты 3, 4, 5.
3. **Ошибка не растёт по цепочке**. Проверка: тест 5.

Ранее измеренное (до этих тестов, из отчёта каскадов 12.10, один прогон каждое):
- изоляция блоков: 0 искажений из 461;
- потеря истины после ошибки статуса «есть → нет»: 100 % → 0 %; ложное «врач» открывает вердикт: 98 % → 12 %; ложный лидер от повторённой жалобы: 28 % → 0 %;
- шина на настоящих блоках почти не переносит ошибки (вред ≤ 5 %);
- бенч «система»: 18/18 против 14/15 у чатов (три сценария);
- цена решения: NNL+API (Flash) 21,5 тыс. токенов и 0 выдумок против API (Max) 4,8 тыс. и 6 выдумок;
- **не решено**: ошибки самого блока на первой фразе (28 %), перепутанное «да/нет» в первом ответе (17 %).

## 3. Условия прогона и честность

- Чаты: новый чат, поиск и инструменты выключены, промт без правок, **один прогон на модель**. Подписи моделей — как прислал автор.
- NNL: из терминала (`NNL/диалог/прогон_шести.py`, режим `код`), без сервера и браузера, кэш ответов выключен.
- Ключи: к тесту 1 — отложенный набор `bench/bench.jsonl` (фраза → номер статьи); к тесту 2 — из текста ст. 34 (графа I) по правилу «более X — строго, до Y — включительно, худший глаз»; к тесту 4 — по ст. 34, 43, 52 (графа I); к тесту 3 — шаблон (6 «вне темы», 3 «да», остальные «нет»); к тесту 6 — перебор всех состояний. К тесту 5 ключа нет.
- Не соблюдено «3 прогона, среднее и разброс»: у чатов один прогон. У NNL-кода три прогона теста 1 (детерминированно одинаковы). Прогон NNL на `qwen3.8-flash` ×3 оборвался: бесплатная квота Alibaba закончилась (HTTP 403).
- **Alice LLM ходила в интернет** вопреки условию «без поиска» (ссылки в ответах 3 и 4), её результаты по тестам 3–4 несопоставимы.
- Тест 4: чистый результат NNL — **5/6 категорий с врачом**. Ошибка была у тяжёлой астмы (пункт «в» вместо «а»). После этого в код добавлен словарь слов степени («тяжёлая», «умеренная»), и стало 6/6. Это подгонка под этот же тест, в зачёт идёт **5/6**.
- Ключ теста 4, случай 7 (ГБ I стадии без поражения органов-мишеней): взят пункт «г» (Б-3); пункт «в» («без нарушения функции») дал бы В. Ключ спорный.
- Тест 2: промт не даёт порогов статьи 34. У NNL документ есть, у чатов нет. Argon дал 24/24 без документа, поэтому тест различает только слабых.

## 6. Что на самом деле измеряла «NNL + API» в первых прогонах

Первые числа NNL (тест 1: 58–70 верных в режиме «свободно», где блоки готовили досье, а модель писала ответ одной строкой) мерили, насколько хорошо **модель переписывает ответ блока**, а не NNL. Цифра NNL без API — **67 или 71 из 88**: ответ даёт блок «здоровье» плюс решатель. Модель в режиме «свободно» только теряла точность (воздерживалась там, где блок знал ответ) и стоила 27–130 тыс. токенов на тест.

Роль API по замыслу: слушатель (слова → факты) и рассказчик (факты → человеческий ответ), а не источник статьи или категории. В бенче API нужен только слушателем в тестах 4–5.

## 7. Что не решено и что нельзя утверждать

- **Ошибки блока на первой фразе**: на тесте 1 из 88 блок неверен в 17 случаях (top-1), в 8 даже при уверенности ≥ 0,5. Это известный долг (28 % по отчёту каскадов).
- **Диалоги 4 и 6** теста 5 (выше).
- **Режим «ядро» не отвечает на пачку в один ход**: это по замыслу диалог с уточнением (то самое «NNL не пропускает ответ без уточнения»). В тесте 4 по одной фразе ядро задало вопрос в 11 из 14 случаев и ни разу не дало вердикта. Поэтому для сравнения с чатами использовался код-режим, а не диалоговое ядро. Нужен «человек-симулятор», который отвечает на вопросы ядра фактами случая; его пока нет.
- Нельзя писать «NNL точнее всех»: у NNL документ и обученные блоки, у чатов нет; один прогон у чатов; ключ теста 4 спорный в одном случае; тест 1 — «домашняя» выборка для блоков.
- Нельзя писать «самая мощная открытая модель — Qwen 3.8»: Kimi K3 по источникам крупнее (2,8 трлн), статус открытости весов Qwen3.8-Max источники трактуют по-разному.
- **Схема-картинка** («куда мы идём») расходится с кодом: «калибровка · предел» нарисована целью, но отвергнута замером; составной блок, «заход 2» и «техкарта = файл» в коде под такими именами не найдены.

## 8. Что нашли и построили по пути (14.10)

- **Причина лага стенда**: один общий замок на ходы всех чатов в `сервер.py` и общий журнал вызовов. Исправлено: замок на каждую сессию, журнал по потокам. Добавлена история чатов (в браузере), новый чат = новая сессия.
- **Лимит Groq** 8000 токенов в минуту на модель: одна GPT-OSS 120B на 88 случаев — 248 с, пул из двух моделей — 9–10 с. Бесплатная квота Alibaba закончилась в ходе прогонов (HTTP 403).
- **Расход токенов NNL+API**: реплика 700–930, итог ~2200, «привет» ~220; режим «свободно v2» (два вызова на случай) — 27–130 тыс. на тест.
- **Правка ядра**: при явном «сам» теперь отзывается прежнее «врач» по тому же факту (`расследование.py`). Тесты защиты: 23/23, диалога 28/28, следа 40/40. Диалог 4 это не вылечило (см. выше).
- **CLI `tiny`** (`C:\BETA\tiny`): другая модель сделала команду `tiny bench`, ключи из `C:\KEY CLAUDE\KEY.txt` читаются сами и нигде не печатаются, сквозной прогон теста 3 прошёл (14/14, 1,7 с), матрица результатов пишется в `матрица.md` и `.csv`. **Экран бенча падает при открытии** (`AttributeError: _live` в `tui/screens/bench.py`, не создан атрибут в `__init__`). Дизайн Lego-экранов не проверялся.
- Выбран один API и одна модель под настройку: `alibaba:qwen3.8-flash` (пресет `flash`), но прогон остановила квота.

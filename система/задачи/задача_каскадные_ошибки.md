# Задача: защита NNL от каскадных ошибок (когда блоков станет много и они плотнее)

Контекст. Проект NNL (Neural Network Lego): матплата, независимые блоки, процессор тактов, ядро причинности, селективный решатель. Код архитектуры в `C:\ЯДРО-ОПЫТ\NNL\`
(`матплата.py`, `процессор.py`, `ядро.py`, `решатель.py`, `линтер.py`, `СТАНДАРТ_БЛОКА.md`, `README.md`). Приложение-диалог (пример использования) в `NNL\диалог\`:
`диалог.py`, `расследование.py` (байесовский учёт по 88 статьям), `блоки.py`. Приоритеты проекта: скорость, качество, экономия токенов.

## Проблема
Ошибка на раннем шаге тянется дальше и усиливается: разбор реплики внешней моделью → оценка блоком → учёт ядром → выбор вопроса → итог.
Уже найдено и частично исправлено: одно слово («близорукость») без степени поднимало вероятность статьи до 0,999, и ядро переставало спрашивать.
Сделано: потолок вклада одной улики по её конкретности (`потолок_улики` в `расследование.py`: 2,5 нат, +1,5 за число, +1,5 за подтверждение врача).
Когда блоков станет много (десятки, независимо обученных), добавятся новые каскады: оценки разных блоков несравнимы, влияние такта 2 на соседей накапливается,
ошибочный вывод одного блока попадает на шину и «подтверждает» другие.

## Что сделать
1. **Измерить, где ошибка течёт.** Написать стенд, который подставляет заранее известные ошибки в каждую стадию (неверный статус «есть» вместо «нет», лишнее
   упоминание, подмена термина, неверный вывод блока на шине) и считает, как меняется итог (рейтинг статей, решение «спросить/итог», число вопросов до остановки).
   Результат: таблица «стадия → во сколько раз ошибка усиливается». Защищать надо там, где течёт сильнее всего.
2. **Предложить и реализовать только то, что подтверждается измерением.** Кандидаты:
   * калибровка вероятностей каждого блока на его собственной выборке (температурное масштабирование), чтобы оценки разных блоков были сопоставимы;
   * учёт улик как журнал с пересчётом с нуля (уточнение человека «нет, не у меня» снимает прошлую улику целиком, а не накладывается сверху);
   * перекрёстная проверка двух независимых путей: оценка блоком всей реплики целиком против разбора по упоминаниям; при расхождении не повышать уверенность, а спросить;
   * ограничение влияния такта 2: вклад чужих выводов по шине не больше заданного предела; конфликт двух блоков по общему понятию — не писать на шину;
   * проверка в `линтере.py` при вставке блока: ответы соседей меняются не более чем на ε (основа есть в `C:\ЯДРО-ОПЫТ\v8\замер\новый_блок.py`: 0,22 % при чтении шины).
3. **К каждому механизму тест, который может покраснеть**, и замер «до → после» на реальных данных (`v8\замер`, `NNL\тест_системы.py`, `NNL\диалог\замер_хода.py`).

## Жёсткие ограничения
* Lego-индекс на такте 1 остаётся 0,0000 (`python NNL/тест_системы.py`). Блок на такте 1 видит только пустую шину.
* В `процессор.py` и `ядро.py` нет имён блоков и предметной области (`if имя == …` запрещено). Всё через паспорта и понятия шины.
* Слепого argmax нет: решение только через решатель с порогом уверенности.
* Предметная область (военкомат, статьи, закон) живёт только в блоках, данных и приложении-диалоге, не в архитектуре NNL.
* Не трогать то, что ведёт другая задача: вызовы API в `диалог.py` (итог, разбор, потоковая выдача), `замер_хода.py`, банк вопросов.
* Автотест `python NNL/диалог/тест_следа.py` должен остаться 40 из 40. Если проверка краснеет из-за намеренного изменения поведения — обновить её и написать почему.
* Тесты не пишут в `~/.nnl/кэш_моделей.jsonl` (см. как это сделано в `тест_следа.py`).

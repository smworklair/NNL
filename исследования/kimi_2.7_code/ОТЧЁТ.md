# Отчёт: Числа как источник выдумок

## Что нового

Детерминированная охрана чисел в NNL ловит только одну узкую группу ошибок: числа с единицами, которых нет в документе и которые при этом попадают в известный фильтру список единиц. Всё остальное — производные значения, неправильный контекст и числа, записанные словами, — остаётся за рамками такой проверки. Эксперимент показал, где именно заканчивается детерминированный метод и начинается необходимость семантики.

## Как проверял

Команда:

```bash
python C:\ЯДРО-ОПЫТ\исследования\kimi_2.7_code\лаба_числа.py
```

Также запускал тест на заведомо плохой реализации:

```bash
python C:\ЯДРО-ОПЫТ\исследования\kimi_2.7_code\тест_падает.py
```

В лабе использовался набор из 18 синтетических кейсов, разделённых по хешу `sha256(id) % 2`. Обучающая половина (10 кейсов) не участвует в отчёте, отчёт по тестовой половине (8 кейсов). В документе ПП РФ № 565 в редакции 2026 найдено 1007 нормализованных чисел.

## Результаты

### Проектная охрана (фиксированный список единиц)

```
=== проектная_охрана ===
Метрики по тестовой половине:

  прямая_выдумка                 n=1  TP=1 FP=0 FN=0 TN=0  (ожидалось/поймано: 1/1)
  прямая_выдумка_неизвестная_единица n=1  TP=0 FP=0 FN=1 TN=0  (ожидалось/поймано: 0/0)
  производное_значение           n=2  TP=0 FP=0 FN=2 TN=0  (ожидалось/поймано: 0/0)
  неправильный_контекст          n=2  TP=0 FP=0 FN=2 TN=0  (ожидалось/поймано: 0/0)
  число_словами                  n=1  TP=0 FP=0 FN=0 TN=1  (ожидалось/поймано: 0/0)
  легитимное_число               n=1  TP=0 FP=0 FN=0 TN=1  (ожидалось/поймано: 0/0)
```

### Расширенная охрана (любая единица после числа)

```
=== расширенная_охрана ===
Метрики по тестовой половине:

  прямая_выдумка                 n=1  TP=1 FP=0 FN=0 TN=0  (ожидалось/поймано: 1/1)
  прямая_выдумка_неизвестная_единица n=1  TP=1 FP=0 FN=0 TN=0  (ожидалось/поймано: 1/1)
  производное_значение           n=2  TP=0 FP=0 FN=2 TN=0  (ожидалось/поймано: 0/0)
  неправильный_контекст          n=2  TP=0 FP=0 FN=2 TN=0  (ожидалось/поймано: 0/0)
  число_словами                  n=1  TP=0 FP=0 FN=0 TN=1  (ожидалось/поймано: 0/0)
  легитимное_число               n=1  TP=0 FP=0 FN=0 TN=1  (ожидалось/поймано: 0/0)
```

### Интерпретация

- **Прямая выдумка с известной единицей**: поймана в 1 из 1 случаев.
- **Прямая выдумка с неизвестной единицей**: не поймана проектной охраной, поймана расширенной. Это показывает, что белый список единиц — узкое горлышко.
- **Производные значения**: не пойманы ни в одном режиме. Если 6 месяцев и 12 месяцев есть в документе, то любая их комбинация выглядит легальной.
- **Неправильный контекст**: не пойман. Число 3 года есть в документе, поэтому его применение к бронхиту не отличается от правильного применения.
- **Число словами**: не поймано, потому что регулярное выражение ищет только цифры.
- **Легитимные числа**: ни разу не ошибочно отмечены как выдумка.

## Ограничения и что не проверено

- Проверена только тестовая половина: 8 кейсов. Это малая выборка.
- Все кейсы синтетические. Не проверено на реальных ответах LLM.
- Не исследованы ложные срабатывания на не-единицах: например, «статья 12» или «пункт 3».
- Не проверены числа без единиц: «более 30», «до 6».
- Не исследованы единицы измерения, записанные через дробь, и сокращённые формы.

## Что взять в NNL

1. **Расширить белый список единиц** или заменить его на более общий паттерн «число + буквенная единица», чтобы не терять выдумки с неизвестными единицами.
2. **Добавить нормализацию чисел словами** («три месяца» → «3 месяца») перед охраной.
3. **Понимать, что охрана чисел — это только первый фильтр**: он ловит явную выдумку, но не может заменить семантическую проверку.

## Что делать следующим

- Исследовать, можно ли детерминированно поймать производные значения через паттерны арифметики («итого», «сумма», «умноженный на», «плюс», «минус»).
- Проверить, можно ли поймать неправильный контекст без LLM через привязку числа к статье/пункту документа.

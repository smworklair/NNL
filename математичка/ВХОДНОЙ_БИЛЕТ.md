## 1. Зачем ты здесь

Честно и по пунктам.

1. **Ручка вместо веры.** Над проектом работают автор и ИИ. Оба уже ошибались: в версии v9.1 проба «успешно проходила» по построению, то есть не могла не пройти. Пример из этой же папки: первый подсчёт таблицы «статья → глава» дал у 10 статей из 88 по две-три главы; причина нашлась (вопросы с несколькими эталонными ответами), таблица пересобрана. Человек, который считает руками, ловит такое первым.
2. **Законодатель выдуманного мира.** Нам нужен тестовый мир с выдуманными болезнями и выдуманными правилами, где правильный ответ известен заранее. Правила должен написать человек до того, как появится код, иначе мир подгонится под нашу архитектуру. Это твоя главная работа (задача 7).
3. **Доказательства.** Одна из главных находок проекта доказывается четырьмя неравенствами 8 класса, а для трёх ответов шестью (задача 5). Она объясняет, почему часть нашей схемы не могла работать.
4. **Проверка «объясни за 5 минут».** Если идею нельзя объяснить учителю алгебры, идея не готова. Ты можешь сказать «не понятно», и это считается результатом.

**Тебе не нужно:** понимать нейросети, писать код, оставаться в проекте дольше, чем интересно.

## 2. Проект в одном абзаце

Мы хотим ИИ из сменных блоков. Блок — небольшая модель, знающая одну область. Вставил блок, и система знает область; вынул, и не знает; остальное при этом не ломается. Полигон: консультации призывников на русском. Блок «здоровье» знает 88 статей Расписания болезней, блок «право» знает около 40 тем (41 в контрольном наборе; законы и постановления). Внутри блока «мешок слов»: вопрос разбивается на слова, у каждого слова есть набор чисел, числа складываются и превращаются в оценки ответов; всего около 3 млн чисел на блок. Каркас, который подключает блоки, проверяет их документы и ведёт журнал, в коде называется «ядро». Ответ выбирается так: каждый блок оценивает **свои** ответы, побеждает самая высокая оценка. Получается «один из блоков», а не одна модель. Цель: чтобы блоки вместе давали вывод, которого не даёт ни один из них по отдельности.

## 3. Словарик

| слово | что это |
|---|---|
| **блок** | маленькая модель, знающая одну область |
| **ядро (v8)** | каркас: подключает и снимает блоки, проверяет, ведёт журнал. «Мозга», который сочетал бы знания блоков, в проекте пока нет |

| **«ничего»** | особый вариант ответа со счётом 0: «не подходит ни один» |
| **зерно** | случайный старт обучения; три зерна = три прогона с разным стартом |
| **п.п.** | процентные пункты: 0,33 → 0,36 это +3 п.п. |
| **перефразы / живые вопросы** | тест на тех же статьях другими словами / настоящие вопросы с форумов |

## 4. Где мы, честно

- **Работает:** каркас (подключить, снять, журнал, 17 проверок при подключении, 26 из 26 тестов); язык из 28 понятий; блок реально можно вынуть, и его знание уходит (в v8: 292 из 293 вопросов «здоровья» после снятия блока ушли в «не знаю» или «уточнить»).
- **Не работает:** «один ум». Оценка блока почти не зависит от соседа: вклад соседа через шину в среднем 0,57 против 9,05 у прямого чтения. На 61 вопросе, где нужны оба блока, вклад соседа составил не меньше 20 % лишь в 6 случаях (задача 12).
- **Нет данных:** в 1157 контрольных вопросах нет ни одного, где нужны оба блока. 61 такой вопрос есть только в обрезанном виде (начало текста и эталон) в `v9/результаты/`.
- **Что поняли:**
  1. сумма оценок не умеет правила вида «сложение по модулю» (твоя задача 5; для 2–6 ответов проверено строго);
  2. общий «ствол» понимания языка нужен, иначе вставленный блок слеп (опыт v9.2);
  3. попытка v9.1 («прозрачность») была декорацией: блоки писали в разные места, ответ считали сами блоки.

Несколько дней работы дали «цель не достигнута» и диагноз. Диагноз — то, что реально есть.

## 5. Версии: варианты или одна линия?

И то и другое: v1–v3 — соревнование разных устройств, v4–v6 — одна линия (ядро общее, блоки растут), v7 — боковой опыт, v8 — перестройка каркаса, v9+ — поиск «одного ума». Версии v2 в репозитории нет.

| версия | что это | что сделано / что вышло |
|---|---|---|
| **v1** | один запрос → один блок-специалист | маршрут по словам-маркерам, без нейросети; измеритель на 461 вопросе |
| **v3** | цепочка «разбор → здоровье или право» против одного монолита | сравнение двух устройств на одних данных |
| **v4** | общее ядро и сменные блоки | блоки v3 перенесены без переучивания: ответы совпали 461 из 461, тесты 12 из 12 |
| **v5** | в ядро вставлена готовая модель «здоровье» из приложения | 608 291 число и 5 212 записей памяти перенесены без переобучения |
| **v6** | право на живых вопросах; отрицание («нет астмы») в ядре | новый проверочный набор из 200 вопросов, закрытый хешем до замеров |
| **v7** | «якоря»: общий формат описания блоков | четыре критерия не выполнены; сам прибор оказался неисправным |
| **v8** | каркас переписан строго: язык из 28 понятий, шина, паспорта, журнал | точных статей знает меньше v6 (68 верных ответов против 107–123), но лучше отсекает вопросы «не про призыв» (88 % против 70–76 %) |
| **v9** | лаборатория «совместность»: 61 вопрос, где нужны оба блока | чужой блок почти не влияет на ответ |
| **v9.1** | попытка «прозрачности» (другим агентом) | не получилось, четыре причины |
| **v9.2** | опыт «общий ствол»; разбор опор; план | вставка блока в замороженный ствол работает, только если ствол знает язык этого блока |

Предсказания к опытам записывались **до** замеров и закрывались хешем (sha256). Мы повторили это для твоих ключей, см. §8.

## 6. Математика, которая уже живёт в проекте

| что | где | по-школьному |
|---|---|---|
| **Вероятность цепочки** | идея ядра, думающего шагами (`v9.2/ОПОРЫ.md`) | если шаг верен с вероятностью p, то d шагов верны с вероятностью p^d |
| **Шансы и их логарифм** | числа на шине (`v8/язык/стандарт.json`) | вероятность p ↔ шансы p : (1 − p); логарифм превращает умножение в сложение |
| **Сборка ответа (softmax)** | `v8/ядро/ядро.py` | e^счёта делим на сумму всех e^счёта; ответы делят между собой единицу |
| **Сжатие 8·tanh(x/8)** | `v8/архитектуры/мешок_шина.py` | около нуля почти x, дальше не выходит за ±8 |
| **Деление на √n** | там же | чтобы сумма не росла вместе с длиной вопроса |
| **Остаток от деления** | слова раскладываются по «корзинам» (crc32 mod 65536) | номер корзины = остаток |
| **Среднее** | смешивание оценок на шине | среднее мнений разных блоков об одном понятии |
| **ECE и AUC** | проверки при подключении блока | ECE: насколько «сказанная» вероятность отличается от настоящей (по 10 корзинам); AUC: доля пар «да / нет», где у «да» число больше |
| **Матрицы, скалярное произведение** | внутри блока | оценка ответа = сумма «число слова × вес» |
| **Таблицы, не раскладывающиеся в сумму** | `v9.2/ОПОРЫ.md` | XOR, сложение по модулю (задачи 4–6) |
| **Малые выборки и разброс зёрен** | `v8/результаты/сводка.md`, `v9.2/результаты/` | 25 вопросов: один вопрос = 4 п.п. (задача 10) |
| **Зависимость ошибок** | `диагностика/стена.md` | общих ошибок 15,4 % вместо 1,5 % (задача 11) |
| **Высокие размерности** | вариант 2 в `v9.2/ОПОРЫ.md` | случайные векторы почти перпендикулярны (задача 14) |

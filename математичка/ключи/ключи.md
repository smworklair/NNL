## 5. Сумма не умеет

Пусть клетка равна 1 тогда и только тогда, когда a_i + b_j > 0, и нужна таблица [[1,0],[0,1]]:

```
a1 + b1 > 0     (клетка 1,1 = 1)
a2 + b2 > 0     (клетка 2,2 = 1)
a1 + b2 ≤ 0     (клетка 1,2 = 0)
a2 + b1 ≤ 0     (клетка 2,1 = 0)
```

Сложим первые два: a1 + a2 + b1 + b2 > 0. Сложим вторые два: a1 + a2 + b1 + b2 ≤ 0. Одна и та же сумма одновременно больше и не больше нуля. Противоречие, таких чисел нет.
Для [[0,1],[1,0]] то же самое с заменой неравенств.

- б) «И» = [[да, нет],[нет, нет]]: a = (1, −2), b = (1, −2). Суммы 2, −1, −1, −4: «да» только в клетке 1,1.
- в) [[да, да],[да, нет]]: a = (1; −0,5), b = (1; −0,5). Суммы 2; 0,5; 0,5; −1: «нет» только в клетке 2,2.
- г) Для таблицы (c + g) mod 3 (ответы 0, 1, 2) нужных оценок A и B не существует: доказательство из шести неравенств ниже. «И» и подобные таблицы сумма выдаёт (пункты б, в).

**Доказательство для (c + g) mod 3** (строки c = 0 и c = 1, все три столбца; оценка ответа y в клетке (c, g) равна A_y(c) + B_y(g), побеждает наибольшая). Нужны шесть неравенств, каждое строгое:

```
клетка (c=0, g=0): A0(0) + B0(0)  >  A1(0) + B1(0)
клетка (c=0, g=1): A1(0) + B1(1)  >  A2(0) + B2(1)
клетка (c=0, g=2): A2(0) + B2(2)  >  A0(0) + B0(2)
клетка (c=1, g=0): A1(1) + B1(0)  >  A0(1) + B0(0)
клетка (c=1, g=1): A2(1) + B2(1)  >  A1(1) + B1(1)
клетка (c=1, g=2): A0(1) + B0(2)  >  A2(1) + B2(2)
```

Сложи все шесть. Левые части в сумме содержат ровно те же слагаемые, что и правые (проверь по списку: каждое A_y(c) и каждое B_y(g) встречается слева и справа одинаково часто). Значит, сумма левых равна сумме правых, а каждое неравенство строгое: получилось «число больше самого себя». Таких чисел нет.

- Для n = 2, 3, 4, 5, 6 то же проверено точным линейным программированием в дробях: для таблицы (c + g) mod n найден набор неравенств, дающий противоречие, и он проверен подстановкой (код выше).
  n = 2: набор из 4 неравенств.
  n = 3: набор из 6 неравенств.
  n = 4: набор из 8 неравенств.
  n = 5: набор из 10 неравенств.
  n = 6: набор из 12 неравенств.
- Вывод для проекта: шина, которая складывает вклады блоков по c и по g, **не может** выдать правило «сложение по модулю». Это не нехватка обучения: таких чисел нет.

## 14. Почти перпендикулярные

- Скалярное произведение двух случайных векторов из ±1 длины D = сумма D независимых ±1: среднее 0, дисперсия D, стандартное отклонение √D. Косинус = произведение / D, стандартное отклонение 1/√D.
- D = 100: теория 0,1000, моделирование 2000 пар: 0,0991.
- D = 10000: теория 0,0100, моделирование 2000 пар: 0,0099.
- D = 10^6: теория 0,001. Доля пар с |косинус| > 3/√D около 0,27 % (правило трёх сигм).
- Смысл для проекта: в больших размерностях случайные векторы почти перпендикулярны, поэтому в один вектор можно сложить много независимых записей (идея суперпозиции из `v9.2/ОПОРЫ.md`).

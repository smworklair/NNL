## 0. Если ты работаешь с ИИ-агентом

Это нормально, и для таких задач полезно: перебор, код, поиск литературы, черновики доказательств. Несколько правил, чтобы результат можно было использовать:

1. **Числа и теоремы проверяй на малых случаях.** Для первой задачи есть точный проверщик `исследование/таблицы.py`: он решает задачу линейным программированием в дробях, без округлений.
2. **Ссылки проверяй по первоисточнику.** Агенты придумывают статьи и номера. Если агент пишет «известно, что…», спроси источник и открой его.
3. **В записке помечай происхождение каждого утверждения:** доказано вручную / посчитано программой (какой) / предложено агентом, не проверено.
4. **Ошибки бывают у всех.** Пример из нашего проекта: в одном из черновиков для таблиц 4×4 стояло число 1066, а программа даёт 6902 (1066 относится к таблицам 3×4). Нашли только потому, что пересчитали.

**Контекст для агента** (можно вставить целиком):

Не придумывай ссылки и числа. Каждое утверждение помечай: доказано (как) / проверено перебором / правдоподобно / неизвестно.

## 1. Таблицы и сложение оценок (центральная задача)

**Постановка.** Дана таблица T: строки r = 1..m, столбцы c = 1..n, в клетке номер ответа из K возможных. Скажем, что T **получается сложением оценок**, если существуют числа A_y(r) и B_y(c) такие, что в каждой клетке (r, c) правильный ответ y = T(r, c) строго лучше всех остальных:

  A_y(r) + B_y(c) > A_z(r) + B_z(c) для всех z ≠ y.

Это в точности то, что делает наша схема: один блок даёт оценки по «строке» (одна часть вопроса), другой по «столбцу», оценки складываются, побеждает наибольшая.

**Что мы посчитали** (программа `исследование/таблицы.py`, точный алгоритм; воспроизводится):

| размер таблицы | ответов K | получается сложением |
|---|---|---|
| 2×2 | 2 | 14 из 16 |
| 2×3 | 2 | 46 из 64 |
| 3×3 | 2 | 230 из 512 |
| 2×2 | 3 | 75 из 81 |
| 2×3 | 3 | 573 из 729 |
| 3×3 | 3 | 9951 из 19683 |

Ещё факты:

- При K = 2 перебором (для 2×2 и 3×3) совпало с правилом «строки таблицы вложены друг в друга как наборы столбцов с „да"». По этому правилу для 4×4 получается 6902 таблицы.
- При K = 3 таблиц 2×2, которые **не** получаются, ровно шесть: «перекрёстные» a, b / b, a при a ≠ b.
- Таблица «сложение по модулю» T(r, c) = (r + c) mod n не получается при n = 2, 3, 4, 5, 6. Для каждого n найден сертификат невозможности из 2n неравенств, которые в сумме дают противоречие (для n = 3 он приведён в `ключи/ключи.md`, задача 5).
- Среди **всех** латинских квадратов порядка 3 (их 12) и порядка 4 (их 576) ни один не получается сложением. Порядки 5 и 6 проверены только для циклических таблиц.

**Вопросы.**

1. Докажи критерий для K = 2: таблица получается сложением ⇔ никакие две строки не «перекрещиваются» (нет подтаблицы 2×2 вида «1, 0 / 0, 1»).
2. Найди условие для K ≥ 3. Подсказка: сертификат невозможности это набор неравенств, у которого все A_y(r) и B_y(c) сокращаются; ищи условие на такие «циклы».
3. Верно ли, что ни один латинский квадрат порядка n ≥ 2 не получается сложением? Для порядков 2, 3, 4 проверено полностью. Доказательства для всех n у нас нет.
4. Найди закономерность в числах 14, 46, 230 (K = 2) и 75, 573, 9951 (K = 3). Продолжи таблицу (например, 2×4 и 3×4), если сможешь.
5. Что минимально нужно добавить к сумме (одно умножение A_y(r)·B_y(c), одну нелинейность), чтобы получалась любая таблица? Это прямой вопрос к устройству системы.

**Что известно из литературы** (по памяти, не проверено, проверь по источнику): задача похожа на «аддитивное измерение» (аксиомы сокращения; Debreu, Luce и Tukey, Scott); числа 14, 230, 6902 совпадают с поли-числами Бернулли и «лонсам-матрицами» (Brewbaker); максимум суммы «по строке» и «по столбцу» это операция из тропической (max-plus) линейной алгебры.

## 2. Ёмкость суперпозиции

**Постановка.** Есть M случайных векторов из чисел ±1 длины D. Берём K из них и складываем. Чтобы достать их обратно, считаем скалярное произведение суммы со всеми M векторами и берём K наибольших. Успех, если взяты именно те K.

**Вопрос.** Как наименьшее D зависит от K и M? Найди асимптотику (подсказка: скалярное произведение суммы с её слагаемым равно D плюс шум; с «чужим» вектором шум без сдвига; сравни по гауссовскому приближению и границе объединения) и сравни с моделированием.

**Что мы посчитали** (`исследование/ёмкость.py`, сетка D грубая: 50, 100, 150, 200, 300, 400, 600, 800, 1200, 1600, 2400, 3200; наименьшее D из сетки с долей успехов не меньше 0,95):

| K (при M = 1000) | 5 | 10 | 20 |
|---|---|---|---|
| D | 150 | 400 | 800 |

| M (при K = 10) | 100 | 1000 | 10000 |
|---|---|---|---|
| D | 300 | 400 | 400 |

То есть по K растёт примерно линейно, по M очень медленно.

**Уточни:** константа в D ≈ c · K · ln M; верна ли такая форма; что меняет «очистка» (подстановка найденного вектора ближайшим из памяти).

## 4. Когда вопросу «нужны оба блока»: формальное определение

Нужно честно назвать, что значит «ответ зависит от двух источников вместе». Пусть X и Y это факты из двух блоков, Z ответ.

**Вопросы.**

1. Посчитай для равномерных входов: I(Z; X), I(Z; Y), I(Z; X, Y) и «взаимодействие» I(Z; X, Y) − I(Z; X) − I(Z; Y) для трёх случаев: Z = XOR, Z = И, Z = (X + Y) mod n.
   Ожидаемо (проверь): для XOR и (X + Y) mod n по отдельности X и Y не дают ничего (I = 0), вместе дают всё; для «И» взаимодействие примерно 0,189 бита, то есть положительное.
2. «И» получается сложением оценок (задача 1), а XOR нет. Значит, одна лишь положительная «синергия» не решает, выразимо правило сложением или нет. Найди характеристику, которая решает (на языке информации или комбинаторики).
3. Предложи определение «вопрос требует обоих блоков» так, чтобы оно проверялось на таблицах.

**Из литературы** (по памяти, проверь): разложение информации на «уникальную», «общую» и «синергетическую» (Williams и Beer, 2010); XOR там пример чистой синергии.

## 5. Сколько вопросов нужно для сравнения двух систем

**Постановка.** Две системы проверяют на одних и тех же n вопросах. Обозначим долю вопросов, где первая верна, а вторая ошибается, через p₁₀, наоборот через p₀₁. Пусть d = p₁₀ + p₀₁ (доля несогласных ответов) и δ = p₁₀ − p₀₁ (разность точностей).

**Вопросы.**

1. Выведи объём выборки n для парного теста (тест Мак-Немара) при уровне значимости α и мощности 1 − β. Мы использовали (по памяти) формулу
   n ≈ [z(α/2)·√d + z(β)·√(d − δ²)]² / δ².
   Для d = 0,2; δ = 0,03; α = 0,05; мощность 0,8 она даёт n ≈ 1742. Моделирование (4000 повторов) даёт мощность 0,798. Проверь вывод.
2. Сравни с точным биномиальным тестом на малых n.
3. Как поправляться, если сравнений много (пять вариантов системы)?
4. Как это связано с зависимостью ошибок из части 3?

## 6. Честный тест как комбинаторная схема

**Постановка.** В выдуманной стране 60 болезней (d), 3 степени (s) и 6 обстоятельств (c). Вопрос это тройка (d, s, c). Нужно выбрать подмножество «для теста» так, чтобы все пары признаков встречались в нём поровну.

**Что у нас есть.** Тройки со степенью s ≡ d + c (mod 3) дают 360 вопросов, в которых каждая пара (болезнь, обстоятельство) встречается 1 раз, пара (болезнь, степень) 2 раза, пара (степень, обстоятельство) 20 раз. Проверено перебором.

**Вопросы.**

1. Докажи, что подмножество, в котором все три типа пар встречаются поровну, возможно только при размере, кратном НОК(180, 360, 18) = 360. То есть «треть» (360 из 1080) единственный нетривиальный вариант.
2. Для подмножеств, где поровну только отдельные признаки (болезни, степени, обстоятельства по отдельности), размер должен быть кратен 60. Докажи, что для каждого такого размера подмножество существует (например, по теореме Холла или потоку).
3. Обобщи на произвольные размеры (D, S, C): когда существует подмножество размера DSC/S с поровну встречающимися парами, и связано ли это с ортогональными массивами (по памяти, проверь)?

Ядро NNL: архитектура

Версия v4. Обычная программа без ИИ, которая держит блоки-знания: подключает, снимает, ведёт к ним вопрос и записывает, кто ответил.

1. Три сущности

Ядро не знает ни одной области. Что передаётся — в типах, что знает система — в блоках, как считать — в архитектурах.

2. Путь вопроса

Алгоритм детерминированный: один и тот же вопрос при тех же блоках идёт тем же путём. Числа заявок — настоящие, вопрос из теста.

шагчто делает ядрокогда «не знаю»
1. входнаходит блоки, чей вход — тип с флагом «запрос»таких блоков нет
2. заявкикаждый входной блок даёт число 0–1; берётся наибольшее, при равенстве — имя по алфавитувсе заявки ниже 0,5
3. цепочкавыход блока отдаётся тому, чей вход совпал по типу и условиюподходящего блока нет; цепочка длиннее 8
4. проверкакаждый выход сверяется с типом, списком ответов блока, проверкой набора (арифметика)блок нарушил тип или посчитал шаг неверно
5. следпишет путь, заявки, версии и хеши блоков— (пишется всегда, с причиной отказа)

3. Подключение блока: десять проверок

Снятие — убрать из реестра; файлы остаются, остальные блоки не трогаются.

4. Блок-область: заявка + знание

5. Типы

типполясмысл
Запросстрокавопрос человека как есть (флаг «запрос»)
Направлениеобласть, текстзаявка признала вопрос своим и передаёт знанию
Ответобласть, вид (выбор | текст), id или текст, итог, p, кандидатыответ человеку (флаг «конечный»)

Типы — данные (набор.json), не код. У каждого типа свой отпечаток sha256: новый тип в наборе старые блоки не ломает, изменённая схема типа — ломает, и ядро такой блок не примет.

6. Паспорт блока

полезачем ядру
вход, выходтип + условие, например Направление[область=здоровье] — по ним строится цепочка
заявкаможет ли блок соревноваться за вопрос
ответызакрытый список id: блок не может назвать то, чего нет в списке
веса: файл, sha256, чиселцелостность и бюджет
типыотпечатки типов, под которые блок обучен
контрольсвой набор вопросов: ядро проверяет, не изменились ли ответы при вставке других блоков
обучение, родительчем и на чём обучен, из какой версии получен

7. След одного ответа

{"вопрос": "вич на ранней стадии",
 "ответ": {"область": "здоровье", "id": "5", "p": 0.988},
 "путь": ["здоровье.заявка", "здоровье"],
 "заявки": [["задачи.заявка", 0.0], ["здоровье.заявка", 1.0], ["команды.заявка", 0.0], ["право.заявка", 0.0]],
 "шаги": [{"блок": "здоровье.заявка", "версия": 1, "sha256": "9411f27d7dfa",
           "вход": "общие:Запрос", "выход": "общие:Направление[область=здоровье]"},
          {"блок": "здоровье", "версия": 1, "sha256": "a948ebdc5609",
           "вход": "общие:Направление[область=здоровье]", "выход": "общие:Ответ[область=здоровье]"}]}

Настоящий след ядра (вопрос из теста, ответ верный — статья 5). Видно, какие именно числа дали ответ: блок, версия, хеш весов.

Слабое место, видное по следу. На вопрос «плоскостопие 3 степени» заявка права дала 0,999998 против 1,000000 у здоровья — здоровье победило на шестом знаке. На тестовых вопросах здоровья заявка права ≥ 0,5 у 2 %. Заявку права стоит доучить на «чужих» фразах.

Ограничения. Вопрос идёт в один блок — на стыке двух областей ядро пока не умеет. Если вынуть и заявку, и знание, 2–20 % вопросов уходят к соседу. Проверено на 4 областях; 30+ — гипотеза.

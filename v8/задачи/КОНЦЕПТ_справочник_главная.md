# Концепт: «Справочник» как главная, «Помощник α» как надстройка

Прототип концепта перенесён в архив: `NNL/диалог/макеты_военкомат/архив/концепт.html` (сервер отдаёт только файлы из корня папки, поэтому прямо открыть его можно, только вернув файлы `концепт.*` обратно в `макеты_военкомат`). Всё из концепта уже встроено в живой макет `http://127.0.0.1:8090/макет/вариация_1_кирпичи_десктоп.html`
Файлы прототипа: `архив/концепт.html`, `концепт.css`, `концепт.js`. Резервные копии живого макета перед правками лежат там же, в `архив`.
Нужен запущенный `сервер.py` (поиск и ползунок берут данные с него; без сервера есть запасной режим).

## Идея одной фразой
Справочник — продукт, который работает **без ключей и без внешней модели**: ядро NNL ищет и объясняет, а категория считается кодом по тексту документа. Чат с ИИ (бывший «Разбор») — необязательная надстройка для тех, кто сам подключил API.

## Структура
| Таб | Роль |
|---|---|
| **Справочник** (главная) | Вход тремя способами, страница статьи, поиск ядром NNL |
| Бумаги | Как сейчас: 13 шаблонов, мастер по шагам |
| Дело | Позже: «общая нагрузка всех функций» — продумать отдельно |
| **Помощник α** | Бывший «Разбор» + экран подключения: провайдер, модель, свой ключ |

## Главная справочника «Справка по запросу» (решение 18.10.2026, поздний вечер)
Главная — это **бланк «Справка по запросу»**, который ядро NNL заполняет, пока человек пишет. Сверху поле «Жалобы — своими словами» (крупное, главное действие), под ним четыре фирменных кирпича приложения: **Слова → Подтвердил → Статья → Пункт** (пустые пунктиром, заполняются по мере ввода), графы «Статья» (с меткой близости), «Пункт» (или «не определён: нужны данные врача»), «Числа» (расчёты по порогам, нажимаются) и кнопка «Открыть статью N» (открывает статью с подсвеченным пунктом). Ниже — «Указатель»: проверка значений, 16 областей, права. Поиск не внизу, а в бланке; когда бланк прокручен вверх за экран, у вкладок появляется круглая кнопка «к полю запроса».
Что отвергнуто на пути сюда: переключатель «Слова · Тело · Исход», Лего-человечек, «Схема», «Задачи», «Редакция», «Панель», «Карта документа», «Циферблат», «Стекло», «Книга», «Ленты», «Разговор» — пользователь сказал, что они «не в стиле приложения» и «не вяжутся с темой»; взяты варианты A «Бланк справки» + C «Сборка решения». Макеты вариантов лежат в `архив/`.
Полоса А–Д на карточках статей и шкала на странице статьи остаются: показывают, какие категории есть в тексте статьи, решение за врачом.

## Умный поиск ядром NNL (что он умеет сейчас)
Запрос `/api/умныйпоиск` (сервер.py, код — `умный_поиск`), без внешней модели:
- блоки «здоровье» и «право» → ближайшие статьи и правовые темы, ворота «не про здоровье / не про право»;
- **числа из слов** («минус 7», «шёпот на 2 метрах», «рост 148, вес 44») → готовый расчёт по порогам из текста статьи (ст. 34, 40, 86, 13), `пороги.из_слов`; то, что человек не назвал, берётся из «нормы» и помечается словами;
- **пункт вместо статьи**: `код_ответ.пункт_по_словам` → «ближе всего пункт «а»»; карточка открывает статью и подсвечивает ступень; пункт не выдумывается, при ничьей его нет;
- **честность**: короткая фраза без чисел и без слов врача (правило из режима «ядро») получает «возможно», а не «очень близко», и подсказку что добавить; исключение — когда все значимые слова фразы есть в тексте самой статьи («диабет» → ст. 13).
Тесты: `тест_умного_поиска.py`, `тест_порогов_справочника.py` (без сети и моделей).

## Страница статьи (сердце концепта)
- Над заголовком шкала **А Б В Г Д**: какие категории вообще возможны в статье и сколько пунктов у каждой.
- **Ползунок** (в прототипе — ст. 34, диоптрии): двигаешь значение, подсвечиваются пункт и категория. Пороги берёт `/api/ст34`, то есть читаются из текста статьи кодом, число страница не угадывает.
- **Лесенка** вместо списка пунктов: от тяжёлого к лёгкому, цвет по категории, числа жирным. Тап по ступени «это про меня» → снизу панель «Если врач подтвердит — категория В: …». Одна короткая оговорка, а не россыпь дисклеймеров.
- **Спросить статью**: строка вопроса, ответ по тексту статьи с проверенными цитатами (`/api/читатель`, уже есть). В прототипе кнопка рабочая, но я её не нажимал: она вызывает модель и тратит токены.
- Внизу стеклянные действия «В моё дело» и «Подать заявление» с мягким размытием, как в макете.

## Что в прототипе настоящее, а что нет
Настоящее: данные 88 статей, поиск ядром (`/api/умныйпоиск`), индикатор «NNL» (зелёный = сервер отвечает), категории и полосы из данных, ползунок ст. 34 по порогам из текста.
Макет: «Права» (3 строки вписаны текстом), табы «Бумаги / Дело / Помощник» (показывают подсказку), «Подать заявление», «В дело» (пишет в отдельный ключ `концепт_дело`, живое дело не трогает).

## Что нужно для пересборки
1. **Ползунки: готово для 4 статей, не для «всех с числами».** Разбор текста всех 88 статей показал, что числовые пороги однозначны только в четырёх: ст. 34 (диоптрии), ст. 40 (слух: шёпот на каждое ухо), ст. 86 (масса и рост) и ст. 13 (ИМТ: недостаточность и пониженное питание). В остальных пункты описательные («со значительным нарушением функций»), число без заключения врача пункта не даёт, и ползунок там был бы выдумкой. Пороги читает `NNL/диалог/пороги.py` из текста статьи, правила проверены тестом `тест_порогов_справочника.py` (граничные значения). Ожирение по ИМТ не считается: степени в тексте нет, они берутся по клиническим рекомендациям. Ст. 35 (острота зрения двух глаз) пока не делал: сочетания слишком сложные.
2. **Простыми словами — готово.** Переключатель «Официально / Простыми словами» над ступенями статьи, выбор запоминается. Пересказ 263 пунктов лежит в `NNL/диалог/простыми_словами.py` (105 пунктов — типовые формулировки, остальное написано вручную); `собрать_простыми_словами.py` проверяет, что ни одно число не выдумано и не потеряно, римские цифры совпали, пункты не пропущены, и собирает `макеты_военкомат/простыми_словами.js`. Модель на странице не вызывается. Формулировки врачом не проверялись: перед выпуском их стоит показать врачу.
3. **Помощник α и свой ключ — готово.** Три режима: «только ядро NNL» (без модели и ключа), «NNL + мой API» (ключ в браузере, уходит заголовками `X-NNL-Key/Provider/Model` на сервер NNL и дальше провайдеру) и «NNL + модель сервера» (режим стенда, если на сервере есть ключи). Ключ не пишется ни в журнал, ни в кэш, ни в тело запроса; при своём ключе серверные ключи не используются вообще, кэш ответов выключен, контекст идёт и в потоки пула. Проверка ключа — запросом списка моделей, токены не тратятся. Тест `тест_личного_ключа.py` (поддельный провайдер на 127.0.0.1) проверяет всё это. Осталось: ключ по http в чужой сети идёт без шифрования — экран предупреждает, но настоящее решение — https.
4. **Код.** `макет.js` — один файл на 115 КБ. Разрезать на экраны (справочник, бумаги, дело, помощник) и общее состояние. Концепт написан отдельными файлами, их можно брать за основу справочника.
5. **Ядро.** «Колет сердце» получает «очень близко» на ст. 42 (p≈0,85) из одной короткой фразы; в Разборе для такого есть правило «слишком мало данных» (потолок 0,45). В поиск это правило не перенесено, решить.
6. **Ошибки блока.** «Повышенный сахар» ядро ставит на ст. 43 (гипертония), а ст. 13 вторая. Если таких будет много — собрать список фраз и либо дообучить блок, либо добавить ключевые слова.

## Риски
- Справочник становится лицом проекта, значит **точность текстов и актуальность ПП № 565 (ред. 2026)** важнее красоты. Юридические ссылки в бумагах нужно показать юристу.
- Подпись «Если врач подтвердит — категория …» — единственная оговорка; следить, чтобы она не превратилась в диагноз.
- Тело и Исход привлекательны, но не заменяют поиск: проверить на людях, чем они пользуются.

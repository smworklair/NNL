## 0. Коротко

**Архитектура по замыслу построена и работает.** Ядро — обычный Python без единого обученного числа (numpy даже не загружает).
Язык NNL-1 — словарь из 28 (+1) понятий с точным смыслом и правила перевода. Блоки — части одной сети: учатся вместе, по той же
формуле, по которой работают, со случайными «выходными». Вопрос проходит два прохода по общей шине, ответ собирается из всех блоков
одной формулой, в журнале точно видно, сколько каждый блок вложил в счёт ответа.

**Контроль — работает, и это измерено:**
- **Вынул блок — его знание ушло.** 292 из 293 вопросов здоровья ушли в «не знаю» или «уточнить», к «праву» — 1. Ответы
  «права» на остальных вопросах изменились у 4,3 %.
- **Без «выходных»** при обучении снятие ломает соседа сильнее: его ответы меняются у 17 %, и он начинает отвечать на 112
  вопросах, где раньше молчал.
- **Вставил новый блок** «команды» (чужой автор, данных старых блоков не видел) в работающую систему. Ответы старых блоков
  изменились у 0,2 %, блок отвечает на свои команды (первый ответ верен у 77,7 %). Сняли его — всё как было: 1061 из 1061.
- **Учёба и работа совпадают.** Ядро и обучение на одних весах расходятся не больше чем на 5·10⁻⁵ (это округление журнала).
- **Ядро не пускает чужое.** Подменённый байт весов, изменённое правило языка, изменённый смысл понятия — во всех трёх случаях

- **Остальное тоже работает:** сбой блока, сессии, заморозка, дообучение одного блока с родителем, замена блока блоком другого

**Качество — честно:**

## 2. Устройство

### 2.1 Язык NNL-1 (`язык/`)
- **Формы токенов:**
  - `с:<основа>` — основа слова (стеммер Snowball для русского, копия внутри языка);
  - `н:<основа>` — отрицаемое слово (правила NegEx, перенесены из v6);
  - `п:<основа>|<основа>` — пара соседних слов;
  - `к:<кусок>` — кусок слова из 3–5 букв;
  - `м:<метка>` — метка: кто:я, кто:другой, время:прошлое, время:будущее, отрицание, вопрос, число.
- **Понятия шины** (версия 1.0 — 28 понятий): область:здоровье, область:право, глава:1 … глава:17 (главы Расписания болезней),
  9 актов права (53-ФЗ, ПП-565, ПП-663, ПП-719, КАС, КоАП, УК, 127-ФЗ, 59-ФЗ). В версии 1.1 добавлено область:команды.
- **Смысл числа на шине.** Это натуральный логарифм шансов, что утверждение понятия верно для этого вопроса. Каждый писатель
  кладёт полную оценку, а на шине лежит их среднее.
- **Ответ** — `ответ:<область>:<id>`. Его счёт — логарифм шансов «верен этот ответ» против опорного «ничего не подходит» (счёт 0).
- **Отпечатки.** Отпечаток правил — sha256 правил, стеммера, форм и меток. Отпечаток понятия — sha256 имени, смысла и общего
  смысла чисел. Блок помнит отпечатки только тех понятий, которые сам читает и пишет.

### 2.2 Ядро (`ядро/ядро.py`)
- **Подключение.** Проверки:
  - есть все поля паспорта;
  - язык и правила совпадают;
  - отпечатки понятий совпадают;
  - ответы записаны по форме языка, область зарегистрирована;
  - sha256 весов совпадает;
  - есть контрольный набор;
  - у ответа один хозяин;
  - блок есть в схеме;
  - бюджет чисел не превышен;
  - код архитектуры загрузил веса;
  - число чисел совпадает с паспортом;
  - «пишет», «читает» и «ответы» в весах совпадают с паспортом;
  - **язык блока на его контроле:** для каждого понятия, которое блок пишет, ECE ≤ 0,10 и AUC ≥ 0,80.
- **Вопрос:** перевод на язык → проход 1 (вклады) → смешивание по схеме → проход 2 (счёты) → сборка → «ответ», «уточнить»
  (область ясна, ответа с p ≥ порога нет) или «не знаю».
- **Журнал** пишет:
  - ответ, причину, сбои;
  - блоки с версиями и 12 знаками sha256;
  - шину и вклады каждого блока;
  - топ-3 ответов с разложением: прямое чтение хозяина + вклад каждого блока через шину + признак присутствия.
    Сумма равна счёту, проверка «сходится».
- **Сессия:** свой журнал и картина сессии (средние числа областей, последние ответы). Закрытие стирает всё.
- **Сбой блока:** исключение → «куска нет» в журнале, ответ из остальных блоков.

### 2.3 Блок «мешок-шина» (`архитектуры/мешок_шина.py`)
- **Вход.** h = сумма векторов токенов / √n. Словарь у блока свой: crc32(соль + токен) mod 65536, размер вектора 48.
- **Проход 1:** c = 8·tanh((h·A + a)/8) для каждого понятия, которое блок пишет.
- **Проход 2:** s = h·U + [числа шины/8, присутствие]·V + b. Счёт линеен по шине, поэтому разложение на вклады точное.
- **Размеры:** «здоровье» — 3 152 682 числа (88 статей), «право» — 3 149 958 (44 темы). Вся система — 6,3 млн чисел.
  Ответ — около 1 мс на процессоре.

### 2.4 Обучение по той же схеме (`обучение/сеть.py`, `обучение/обучить.py`)
- **Шаг обучения.** Пакет из 64 вопросов проходит те же формулы, что в ядре. Потеря: перекрёстная энтропия ответа плюс
  логистическая потеря каждого понятия у каждого писателя: язык требует, чтобы его число было откалиброванным.
- **Градиент.** Через шину он к писателю не идёт: число на шине значит то, что сказано в языке, а не скрытый код для соседа.
- **«Выходные».** В каждом примере каждый блок отсутствует с вероятностью 0,3. Его ответы исчезают из softmax, вклады — с шины.
  Если верный ответ был его, цель — «ничего».
- **Данные** (только train; dev — для остановки):
  - здоровье: статьи, пункты, lay, учитель;
  - право: lex и тексты тем;
  - живые пулы 1+2 (Claude, Muse Spark): 15 % — dev; почти-повторы всех проверочных наборов выброшены;
  - фон v2.
  Итого 39 501 строка обучения, 2 357 — dev.
- **Подбор на dev:**
  - lr 0,01: при 0,003 хуже;
  - свёртка √n: среднее учится медленнее;
  - масштаб чтения шины 8: без него второй проход терял 1,5–3 п.п. на dev;
  - градиент через шину выключен: dev 0,7558 против 0,7523;
  - шум на шине не помог.
  Потом 3 зерна на каждое устройство.

### 2.5 Как проходит вопрос (из `результаты/пример_журнала.json`)
- **«у меня нет астмы, но сильная аллергия на пыльцу. возьмут в армию?»**
  - Язык нашёл отрицание «нет · астмы»: астма пошла как `н:астм`, без кусков слова.
  - На шине: область:здоровье = +6,29 (p ≈ 0,998), область:право = −7,66.
  - Ответ — ст. 84, p = 0,83. Счёт 3,73 = прямое чтение «здоровья» 4,40 + вклад «права» через шину 0,54 + присутствие −1,21.
  - Ст. 52 «астма» в кандидаты не попала. Верна ли ст. 84 для поллиноза, я не проверял: пример показывает механику.
- **«У меня плоскостопие 3 степени, а пришла повестка…»** → «уточнить: право» (p = 0,98), ни одна тема не набрала 0,5.
  «Здоровье» сочло вопрос не своим (область:здоровье = −5,17), хотя ст. 68 здесь к месту. Вопросы на стыке — слабое место (§6).
- **«посоветуйте хороший ноутбук для учёбы»** → «не знаю», p «ничего» = 1,00.

## 6. Что не получилось и почему

1. **Шина не дала качества на этой задаче.** Оба блока читают весь вопрос и учатся на всех данных. Мысль соседа (область, глава,
   акт) почти ничего не добавляет к тому, что блок видит сам. Где шина должна работать:
   - блоки видят разное: текст закона, справочник, документы человека;
   - блоки знают разное: новый блок не видел чужих данных (§5.6 — там шина помогла).
2. **Конкретика хуже v6.** Верных статей и тем вдвое меньше, а право у основной ещё и сильно скачет по зёрнам (59–71 %).
   Блоки — линейные мешки на 3 млн чисел. В v6 здоровье отвечала модель-приложение (BM25 + память фраз).
3. **Вопросы на стыке областей** («плоскостопие + повестка»). Ответ один, а нужен ответ от обоих блоков сразу. Сборка в v8
   выбирает один лучший ответ. Выдавать по ответу на каждую уверенную область — правка формулы в схеме, но на это нужна разметка.
4. **Сессия держит картину, но в ответ её не подмешивает.** Это нужно учить на диалогах, а их в данных нет.
5. **Язык пока беден.**
   - Метки «кто», «время», «вопрос» стоят, но их смысл блоки берут только из данных.
   - «Факта» в языке нет.
   - Отрицание — правила v6 с прежними ошибками («сколиоза нет, спина ровная» — убирает не ту сторону).
6. **Проверка языка блока неполная.** Глава 3, глава 15, «акт:укрф», «акт:127фз» и «акт:59фз» не проверены на контроле:
   в dev меньше 10 примеров.
7. **Оговорки к данным.**
   - Разметка — ИИ, не эксперт.
   - Свежие 2 и 3 уже использовались в замерах v6.
   - Флагманы не запускались: нужны ключи API. Ответы v8 на 600 лежат в `результаты/ответы_600/`. Чтобы v8 попала в их
     таблицу, скопируйте `v8_основная.з1.jsonl` в `флагманы/ответы/`.
   - Размер системы — 6,3 млн чисел, ниже вашей цели 10–100 млн.

## 7. Что дальше (по порядку пользы)

1. **Дать блокам разное зрение.** Например, блок «документы» читает текст статей закона и Расписания, его находки идут
   по шине. Это прямая проверка, нужна ли шина.
2. **Ответ на стыке:** формула сборки «по ответу на каждую уверенную область».
3. **Порог ответа на схему** выбирать по dev под заданную долю ошибок (Learn-then-Test), а не 0,5.
4. **Сильнее блок здоровья** под этот же стандарт: BM25 и память фраз внутри блока, вклады на шину.

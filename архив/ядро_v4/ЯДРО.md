# Ядро NNL — архитектура

Ядро — обычная программа на Python: 674 строки, два файла (`ядро/схема.py` — типы, `ядро/ядро.py` — управление).
В нём **нет ни одного обученного числа**, оно не читает и не понимает текст и ничего не знает о военкомате, задачах
или любой другой области. Без блоков оно запускается и на любой запрос отвечает «не знаю».
Использует только стандартную библиотеку (numpy и torch не загружает, это проверяется тестом).

## 1. Из чего состоит система

```
запрос человека
      │
      ▼
┌─────────────────────── ЯДРО ───────────────────────┐
│  типы (папка типы/)   ·  реестр блоков   ·  маршрут │
│  след   ·  отказ «не знаю»   ·  контроль  ·  бюджет │
└───────┬───────────────────────────────┬────────────┘
        │ вызывает код архитектуры      │ читает паспорт
        ▼                               ▼
  архитектуры/*.py (код без весов)   блоки/<имя>/ {веса.npz, паспорт.json}
```

Три сущности, и у каждой своя папка:
- **Типы** — описание «что можно передавать»: запрос, направление, ответ и т. п. Лежат в `типы/<набор>/набор.json`.
- **Блок** — папка с файлом весов и паспортом. Единственное место, где есть обученные числа.
- **Архитектура** — код, который умеет считать по весам блока (сеть без весов). Это код типа блока, ИИ он не считается.

## 2. Типы

Набор типов описывается данными, а не кодом. Ядро не знает ни одного типа само, оно читает схему:

| вид схемы | что значит |
|---|---|
| строка, число, целое, логическое | простые значения; у чисел можно задать границы |
| перечисление | значение из списка (список в файле или словарь списков) |
| список, кортеж, запись | составные значения |
| вероятности | словарь «ключ → число в [0, 1]» |

У типа есть флаги: `запрос` (вход от человека) и `конечный` (ответ человеку).
Что схемой не выразить, например «каждый шаг решения посчитан верно», лежит в `проверки.py` набора типов — это код набора, не ядра.

Сейчас в наборе `общие` три типа: `Запрос → Направление{область, текст} → Ответ{область, вид, id | текст, итог, p}`.

**Отпечаток типа.** У каждого типа свой sha256 (схема + перечисления, на которые он ссылается + код проверки). Блок помнит отпечатки своих
типов. Добавили новый тип в набор — старые блоки не ломаются; изменили схему типа блока — ядро его не примет.

## 3. Блок и паспорт

Паспорт (`паспорт.json`) — маленький файл, и ядро по нему решает всё:

| поле | что в нём |
|---|---|
| имя, версия, роль, область | кто это |
| вход, выход | тип + условие, например `Направление[область=здоровье]` |
| архитектура | какой код считает по весам |
| заявка | может ли блок подавать заявку «насколько вопрос мой» |
| ответы | закрытый список id, которые блок может назвать |
| веса | файл, sha256, число обученных чисел |
| типы | отпечатки типов, под которые блок обучен |
| контроль | свой контрольный набор вопросов |
| обучение, родитель | чем и на чём обучен, из какой версии получен |

## 4. Что ядро делает при подключении блока (`attach`)

Блок не подключается, если не пройдена хоть одна проверка:
1. в паспорте есть все обязательные поля;
2. типы входа и выхода существуют, условия на поля допустимы;
3. отпечатки типов совпадают с текущими;
4. файл весов есть и его sha256 равен записанному;
5. код архитектуры загружает веса;
6. число чисел в весах равно записанному в паспорте;
7. классы блока совпадают с перечислением выходного типа и списком `ответы`;
8. нет второго блока с тем же входом (конфликт);
9. несколько входных блоков допустимы только если каждый умеет подавать заявку;
10. не превышен бюджет чисел (если задан).

Снятие (`detach`) убирает блок из реестра. Файлы остаются, остальные блоки не трогаются, перезапуск не нужен.

## 5. Как ядро ведёт запрос

Алгоритм полностью детерминированный. Обученного классификатора и вызовов модели в роли маршрутизатора нет.

1. **Вход.** Находятся блоки, чей вход — тип с флагом `запрос`.
2. **Заявки.** Если входной блок один и заявки не подаёт, он получает всё. Иначе каждый подаёт заявку — число от 0 до 1.
   Побеждает наибольшая, при равенстве — имя по алфавиту. Если наибольшая меньше порога 0,5 — ответ «не знаю».
3. **Цепочка.** Выход блока идёт тому блоку, чей вход (тип + условие) ему подходит. Цепочка кончается на типе с флагом `конечный`.
4. **Проверка каждого шага.** Выход блока сверяется с типом, условием выхода, списком его ответов и проверкой набора типов.
   Если блок вернул нарушающее тип значение, ядро не передаёт его дальше и отвечает «не знаю» с причиной.
5. **Отказ.** Нет подходящего блока, нет победившей заявки, цепочка длиннее 8 шагов, неоднозначность — всегда «не знаю» с записанной причиной.

## 6. След

На каждый запрос ядро записывает: вопрос, ответ, путь (список блоков), заявки всех блоков, каждый шаг (блок, версия, 12 знаков sha256 весов,
входной и выходной тип) и причину отказа. Запись по желанию уходит в файл, по одной строке на запрос.
Так видно, какие числа участвовали в ответе.

## 7. Доступ к параметрам

| функция | что делает |
|---|---|
| `params(имя)` | список параметров блока: имя, форма, число чисел |
| `param_values(имя)` | сами массивы (для проверки сравнением) |
| `freeze` / `unfreeze` | заморозка: замороженный блок дообучить нельзя |
| `finetune(имя, данные)` | дообучить **один** блок. Данные проверяются по типу входа. Результат — новая версия `имя@N` в своей папке с ссылкой на родителя в паспорте, старый файл не меняется |

## 8. Контроль при вставке и целостность

- `control()` прогоняет контрольные наборы всех блоков через полный маршрут.
- `attach_checked()` делает снимок до вставки блока и после и показывает, сколько ответов у других блоков изменилось.
- `total_numbers()` и бюджет: сколько чисел в системе и не превышен ли лимит.

## 9. Чего ядро не делает (и не должно)

- не понимает текст и не выбирает область по смыслу — за это отвечают блоки-«заявки»;
- не знает, что такое «здоровье», «право» или «задача»: всё это лежит в данных (типы, паспорта);
- не обучается и не содержит чисел из обучения.

## 10. Проверено

| что | результат |
|---|---|
| тесты ядра на блоках-пустышках | 14 из 14 |
| пустое ядро | «не знаю» на любой запрос, numpy и torch не загружены |
| блоки v3 (написанные под другое ядро) на ядре v4 | ответы совпали 461 из 461 |
| вставка новой области | изменилось 0,4 % ответов старых областей |
| вынутое знание | 99–100 % вопросов области → «не знаю» |
| случайная вставка и снятие, 40 шагов, 12 180 ответов | 0 нарушений, 0 изменённых файлов, след без потерь |

## 11. Ограничения

- Если снять и «заявку», и «знание», до 2–20 % вопросов области уходят к соседу вместо «не знаю».
- Вопрос идёт ровно в один блок; вопросы на стыке двух областей ядро пока не обрабатывает.
- Ядро проверено на 4 областях и 8–10 млн чисел; на 30 и более не проверялось.
